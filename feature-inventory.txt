====================================================================
ACCESS-CONTROL PATTERNS (summary)
====================================================================
- Platform superadmin only: PlatformOrganizationController, PlatformSetupController, PlatformStatsController,
  PlatformSubscriptionController, PlatformAnalyticsController, SystemPromptAdminController, RagDocumentAdminController.
- Tenant admin tier (ORG_ADMIN/PLATFORM_ADMIN, often + MANAGER/TL): most write/config endpoints — users, roles,
  calendars, column schemas, message templates, KPIs, NPA, risk scoring, reconciliation, file uploads, feature-flag admin.
- Field-agent self-service (FO + supervisors): visit logs, PTPs, collections submission, non-contactables,
  agent field ops (shifts/SOS/location), attendance check-in.
- Cross-tenant isolation: nearly every controller derives organizationId from the JWT (never trusts client-supplied
  org id for tenant users); PLATFORM_ADMIN gets cross-org reads via an isPlatformAdmin()/assertSameTenant() pattern,
  returning 404 (not 403) to tenant users reaching for another org's data. Some routes log platform-admin cross-org
  access via PlatformAdminAccessGuard for auditability (FileUploadController, MessageTemplateController, SosAudioWebSocketHandler).
- Public/unauthenticated: auth register/login/refresh/forgot-password, ContactController, PaymentLinkResolveController
  (/p/{token}), StripeWebhookController (signature-verified instead of JWT).
